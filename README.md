# LLM Gateway

Единая точка входа для всех ИИ-интеграций. Сервисы обращаются к одному
HTTP-эндпоинту с внутренним токеном и просят **класс модели**, а не конкретную
вендорскую модель. Шлюз решает, какая реальная модель сегодня обслуживает этот
класс, следит за бюджетами и переживает падение отдельного провайдера.

> Потребитель просит класс возможностей («дёшево-быстро», «умная»), шлюз
> решает, что это значит сегодня.

```
потребители ──Bearer sk-gw-*──▶ Caddy (TLS) ──▶ LiteLLM Proxy ──▶ Anthropic
   (n8n, боты, сервисы)                            │                 OpenAI
                                                   ├── Postgres  (ключи, бюджеты, spend-логи)
                                                   └── Redis     (rate-limit, кэш)

                        gwctl (Go CLI) ──Admin API──▶ LiteLLM Proxy
                              ▲
                        config/*.yaml в git  ← источник правды
```

**Data plane** — LiteLLM Proxy, взятый как есть: в горячем пути нет своего кода.
**Control plane** — `gwctl`, отдельный статический бинарник: обновление прокси
не должно ломать управление ключами.

---

## Быстрый старт

```bash
cp deploy/.env.example deploy/.env && vim deploy/.env   # домен и секреты
make validate          # проверить конфиг локально
make up                # поднять стек: litellm, postgres, redis, caddy
make apply             # залить в прокси алиасы и настройки
make health            # всё должно быть зелёное
make key-issue CONSUMER=my-telegram-bot                 # ключ печатается один раз
make smoke             # прогнать контракт живыми запросами
```

`make` без аргументов печатает список целей.

## Алиасы

| Алиас | Смысл | Первичная модель | Fallback |
|---|---|---|---|
| `cheap-fast` | Классификация, извлечение, роутинг | `claude-haiku-4-5` | OpenAI дешёвый tier |
| `balanced` | Рабочая лошадка, ~80% трафика | `claude-sonnet-5` | OpenAI средний tier |
| `smart` | Сложные задачи, качество важнее цены | `claude-opus-5` | OpenAI флагман |
| `reasoning` | Многошаговые рассуждения | `claude-opus-5` + thinking | **нет** |
| `long-context` | Большой вход | `claude-sonnet-5` | OpenAI 1M-модель |
| `vision` | Картинки на вход | `claude-sonnet-5` | OpenAI флагман |
| `embed-fast` | Эмбеддинги, дёшево | `text-embedding-3-small` | **нет** |
| `embed-quality` | Эмбеддинги, качество | `text-embedding-3-large` | **нет** |

Три алиаса живут без fallback осознанно: у Anthropic нет embeddings API, а
поведение extended thinking у вендоров различается настолько, что подмена
модели молча изменила бы характер ответа. `GET /v1/models` этого не скрывает.

Актуальный маппинг всегда виден в `make models`; текущий состав задаётся в
[`config/models.yaml`](config/models.yaml).

## Структура репозитория

```
config/          источник правды: алиасы, потребители, поведение прокси
cmd/gwctl/       CLI control plane
internal/
  config/        парсинг и валидация config/*.yaml
  litellm/       клиент Admin API
  reconcile/     построение и применение плана изменений
  report/        форматирование вывода (table / json)
deploy/          docker-compose, Caddyfile, .env.example, генерируемый конфиг прокси
docs/            контракт, справочник CLI, runbook
test/smoke/      smoke-тест контракта против поднятого стека
```

## Разработка

```bash
make build       # bin/gwctl
make test        # go test ./... -race -cover
make lint        # golangci-lint
make fmt         # gofmt + goimports
```

Изменения в `config/*.yaml` проверяются локально (`make validate`), затем
план (`make apply-dry`), затем применение (`make apply`). Повторный `make apply`
обязан напечатать `no changes` — это проверяется тестом, а не обещанием.

Конфиг под git не случайно: он бесплатно даёт историю «кто когда получил
доступ к чему».

## Безопасность

* Вендорские ключи не покидают VPS: живут в `deploy/.env`, доступны только
  контейнеру прокси. В конфиге хранится ссылка на переменную окружения, не
  значение.
* Потребитель не может обратиться к вендору напрямую — единственный публичный
  интерфейс описан в [docs/CONTRACT.md](docs/CONTRACT.md).
* У каждого ключа свой whitelist алиасов: принцип наименьших привилегий.
* Секрет ключа печатается один раз при выпуске; в БД лежит хэш.
* Тела запросов и ответов не логируются — только метаданные.
* Мастер-ключ LiteLLM используется только `gwctl` и никогда не выдаётся
  потребителям.

`make validate` заодно проверяет, что в `config/` нет секретов, а `.env`
закрыт `.gitignore`.

## Лицензия и версионирование

SemVer, версия в [CHANGELOG.md](CHANGELOG.md) и git-теге `vX.Y.Z`. Ремап алиаса
на другую вендорскую модель — **PATCH**: потребители не замечают, и это ровно
тот случай, ради которого строился шлюз.

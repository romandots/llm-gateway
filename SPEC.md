# LLM Gateway — техническое задание

**Статус:** утверждён
**Дата:** 2026-08-12
**Версия документа:** 1.0

---

## 1. Цель

Единая точка входа для всех ИИ-интеграций: сервисы и проекты обращаются к одному
HTTP-эндпоинту с внутренним токеном и просят **класс модели**, а не конкретную
вендорскую модель. Шлюз решает, какая реальная модель сегодня обслуживает этот
класс, следит за бюджетами и переживает падение отдельного провайдера.

### Ключевой принцип

> Потребитель просит класс возможностей («дёшево-быстро», «умная»), шлюз решает,
> что это значит сегодня.

Если воркер может попросить `claude-haiku-4-5`, конфигурация потребителя прибита
к вендору и смысл шлюза потерян. Поэтому вендорские имена моделей на входе
**запрещены на уровне механизма**, а не соглашения (см. §3.3).

### Нефункциональные требования

| Параметр | Значение |
|---|---|
| Нагрузка | единицы–десятки RPS, несколько проектов-потребителей |
| Развёртывание | Docker Compose на одном VPS |
| Таймаут запроса | ≤ 30 s (включая внутренние ретраи и fallback) |
| Логирование тел запросов/ответов | запрещено (только метаданные) |
| Доступность | best effort; деградация через fallback-провайдера |

## 2. Архитектура

```
потребители ──Bearer sk-gw-*──▶ Caddy (TLS) ──▶ LiteLLM Proxy ──▶ Anthropic
   (n8n, боты, сервисы)                            │                 OpenAI
                                                   ├── Postgres  (ключи, бюджеты, spend-логи)
                                                   └── Redis     (rate-limit, кэш)

                        gwctl (Go CLI) ──Admin API──▶ LiteLLM Proxy
                              ▲
                        config/*.yaml в git  ← источник правды
```

### 2.1 Data plane — LiteLLM Proxy

Берётся как есть, в горячем пути нет своего кода. Даёт из коробки: виртуальные
ключи, бюджеты per-key, алиасы моделей, ретраи, fallback между деплойментами,
OpenAI-совместимый формат, учёт стоимости.

Зависимости: Postgres (состояние ключей, бюджетов, spend-логов), Redis
(распределённый rate-limit и кэш), Caddy (TLS + reverse proxy).

### 2.2 Control plane — `gwctl`

Собственный CLI на Go. Читает декларативный конфиг из `config/` и приводит
состояние прокси к описанному (idempotent reconcile через LiteLLM Admin API).

**Почему отдельный бинарник, а не Python-скрипт внутри образа LiteLLM:**
control plane не должен зависеть от питоновского окружения data plane — иначе
обновление LiteLLM ломает управление ключами. Один статический бинарник кладётся
и на VPS, и на рабочую машину.

**Почему CLI, а не своё HTTP API:** потребителей единицы, операции редкие и
ручные. Git даёт бесплатно историю «кто когда получил доступ к чему».

## 3. Публичный контракт

Всё, что описано в этом разделе, — обязательства перед потребителями. Ломать
их дорого: контракт зашит во все интеграции.

### 3.1 Endpoints

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/v1/chat/completions` | Чат: streaming, tools, structured output, vision |
| `POST` | `/v1/embeddings` | Эмбеддинги |
| `GET` | `/v1/models` | Алиасы, доступные текущему ключу, + матрица возможностей |
| `GET` | `/health/liveness` | Жив ли процесс (без auth) |
| `GET` | `/health/readiness` | Готов ли обслуживать (БД, Redis) — без auth |

Формат запроса и ответа — OpenAI-совместимый. Никаких собственных расширений в
теле запроса.

### 3.2 Аутентификация

```
Authorization: Bearer sk-gw-<consumer>-<random>
```

Префикс с именем потребителя — чтобы по ключу, найденному в чужом логе, сразу
понимать, чей он и что отзывать. Случайная часть — не менее 32 символов из
криптографического источника.

### 3.3 Алиасы моделей — жёсткий запрет вендорских имён

Поле `model` принимает **только** алиас из §4. Запрет реализуется двумя
независимыми барьерами:

1. **В `model_list` прокси существуют только алиасы.** Вендорских имён там нет
   физически, поэтому запрос `claude-opus-5` не имеет цели для маршрутизации.
2. **У каждого ключа заполнено поле `models`** — whitelist разрешённых этому
   потребителю алиасов. LiteLLM отклоняет запрос до обращения к провайдеру.

Второй барьер обязателен: он же реализует принцип наименьших привилегий —
потребителю, которому нужен `cheap-fast`, не выдаётся `smart`.

Неизвестный алиас или вендорское имя → `400`:

```json
{
  "error": {
    "code": "unknown_model_alias",
    "message": "Model 'claude-opus-5' is not a valid alias. Use one of the available aliases.",
    "available": ["cheap-fast", "balanced"],
    "type": "invalid_request_error"
  }
}
```

### 3.4 Ответ

Стандартный OpenAI-формат. Дополнительно:

- **`usage` присутствует всегда**, включая streaming. Шлюз принудительно
  выставляет `stream_options.include_usage = true`, даже если потребитель этого
  не сделал.
- **Заголовки ответа:**
  - `x-gw-model` — реальная модель, которая отработала запрос
  - `x-gw-alias` — запрошенный алиас
  - `x-gw-fallback` — `true`, если сработал fallback-провайдер
  - `x-gw-request-id` — идентификатор для корреляции с логами шлюза

### 3.5 Ошибки

| Код | Когда | Тело |
|---|---|---|
| `400` | Нарушен контракт: неизвестный алиас, невалидный запрос | `error.code`, `error.message`, при `unknown_model_alias` — `available` |
| `401` | Ключ невалиден, отозван или истёк | `error.code = invalid_api_key` |
| `403` | Ключ валиден, но алиас ему не разрешён | `error.code = alias_not_permitted`, `available` |
| `429` | Исчерпан дневной бюджет или rate-limit | `error.code = budget_exceeded` \| `rate_limit_exceeded`, `retry_after`, `budget.limit_usd`, `budget.spent_usd`, `budget.resets_at` |
| `502` | Все провайдеры под алиасом вернули ошибку | `error.code = upstream_error` |
| `504` | Превышен таймаут 30 s | `error.code = upstream_timeout` |

**Принцип:** ретраи и fallback — зона ответственности шлюза, наружу не
протекают. Потребитель видит либо успех, либо финальную ошибку, и никогда не
ждёт дольше 30 s.

Тело `429` должно быть достаточным, чтобы потребитель принял решение без похода
в документацию:

```json
{
  "error": {
    "code": "budget_exceeded",
    "message": "Daily budget for consumer 'tansultant-reactivation' exhausted.",
    "type": "rate_limit_error"
  },
  "retry_after": 18240,
  "budget": {
    "limit_usd": 5.0,
    "spent_usd": 5.02,
    "period": "daily",
    "resets_at": "2026-08-13T00:00:00Z"
  }
}
```

### 3.6 `GET /v1/models` — самодокументация контракта

Возвращает алиасы, доступные **текущему ключу**, с матрицей возможностей. Это
важнее, чем кажется: потребитель узнаёт, поддерживает ли `cheap-fast` сегодня
tools, не читая конфиг шлюза и не спрашивая владельца.

```json
{
  "object": "list",
  "data": [
    {
      "id": "cheap-fast",
      "object": "model",
      "owned_by": "llm-gateway",
      "capabilities": {
        "streaming": true,
        "tools": true,
        "json_schema": "emulated",
        "vision": false,
        "embeddings": false
      },
      "context_window": 200000,
      "max_output_tokens": 64000
    }
  ]
}
```

`json_schema` — трёхзначное поле: `native` (провайдер гарантирует валидность),
`emulated` (шлюз/LiteLLM эмулирует через промпт, гарантий нет),
`unsupported`.

### 3.7 Поддерживаемая функциональность

| Возможность | Статус | Замечание |
|---|---|---|
| Streaming (SSE) | обязательна для всех chat-алиасов | `usage` в финальном чанке |
| Tools / function calling | обязательна для всех chat-алиасов | `tools`, `tool_choice`, `tool_calls` |
| Structured output (`response_format` c `json_schema`) | обязательна, статус per-alias | см. §3.6 |
| Vision (image_url / base64) | гарантирована только для алиаса `vision` | см. ниже |
| Embeddings | только алиасы `embed-*` | отдельный endpoint |

**О vision.** Шлюз не блокирует картинку на не-vision алиасе искусственно: такая
проверка требовала бы разбора тела запроса в горячем пути, а часть моделей под
другими алиасами картинки всё равно понимает. Гарантия даётся только по алиасу
`vision`; на остальных поведение определяется провайдером и честно отражено
флагом `capabilities.vision` в `GET /v1/models`. Потребитель, которому нужны
картинки, обязан использовать `vision`.

**О матрице возможностей.** Флаги в `capabilities` — это *декларация* в
`models.yaml`, а не автоопределение. Расхождение декларации с реальностью —
дефект конфига, и smoke-тесты (§12) проверяют каждый заявленный флаг реальным
запросом.

## 4. Таксономия алиасов

Список **закрытый**. Новые алиасы добавляются, существующие не переименовываются
и не меняют смысл — это публичный контракт.

| Алиас | Смысл | Первичная модель | Fallback |
|---|---|---|---|
| `cheap-fast` | Классификация, извлечение, роутинг, простые преобразования | `claude-haiku-4-5` | OpenAI дешёвый tier |
| `balanced` | Рабочая лошадка, ~80% трафика | `claude-sonnet-5` | OpenAI средний tier |
| `smart` | Сложные задачи, длинные инструкции, качество важнее цены | `claude-opus-5` | OpenAI флагман |
| `reasoning` | Многошаговые рассуждения | `claude-opus-5` + adaptive thinking | — |
| `long-context` | Большой вход (сотни тысяч токенов) | `claude-sonnet-5` (1M) | OpenAI 1M-модель |
| `vision` | Картинки на вход | `claude-sonnet-5` | OpenAI флагман |
| `embed-fast` | Эмбеддинги, дёшево | `text-embedding-3-small` | **нет** |
| `embed-quality` | Эмбеддинги, качество | `text-embedding-3-large` | **нет** |

### 4.1 Явные ограничения

1. **Три алиаса живут без fallback.** У `embed-fast` и `embed-quality` — потому
   что у Anthropic нет embeddings API: падает OpenAI → падают эмбеддинги. У
   `reasoning` — потому что поведение extended thinking у вендоров различается
   настолько, что подмена модели молча изменила бы характер ответа; лучше честная
   ошибка, чем тихая деградация. Это структурные свойства выбранной пары
   провайдеров, а не недоделка, и `GET /v1/models` их не скрывает.
2. **Точные OpenAI-идентификаторы моделей уточняются при реализации** запросом к
   `GET https://api.openai.com/v1/models`. Линейка OpenAI за последний год
   перетасовывалась; данные о ней получены из агрегаторов цен, а не от вендора.
   Anthropic-идентификаторы (`claude-opus-5`, `claude-sonnet-5`,
   `claude-haiku-4-5`) сверены с официальной документацией.
3. **`json_schema` у Anthropic и OpenAI реализован по-разному.** LiteLLM
   транслирует между форматами, но гарантии валидности не идентичны. Статус
   per-alias честно отражается в `GET /v1/models`.

### 4.2 Правило маршрутизации

Порядок `targets` в конфиге = порядок приоритета. Первая цель — основная,
последующие — fallback. Fallback срабатывает на: `429` от провайдера, `5xx`,
таймаут соединения. **Не** срабатывает на `400` (ошибка в самом запросе — она
детерминированная, повтор на другом провайдере даст то же самое).

## 5. Control plane: `gwctl`

### 5.1 Конфигурация

Три файла в `config/`, все под git. Секретов в них нет.

#### `config/models.yaml`

```yaml
version: 1

aliases:
  cheap-fast:
    description: "Классификация, извлечение, роутинг. Дёшево и быстро."
    capabilities:
      streaming: true
      tools: true
      json_schema: emulated
      vision: false
    context_window: 200000
    max_output_tokens: 64000
    targets:
      - provider: anthropic
        model: claude-haiku-4-5
      - provider: openai
        model: <уточняется при реализации>

  balanced:
    description: "Рабочая лошадка. Дефолт для большинства задач."
    capabilities:
      streaming: true
      tools: true
      json_schema: native
      vision: false
    context_window: 1000000
    max_output_tokens: 128000
    targets:
      - provider: anthropic
        model: claude-sonnet-5
      - provider: openai
        model: <уточняется при реализации>

  # ... остальные алиасы по §4
```

#### `config/consumers.yaml`

```yaml
version: 1

consumers:
  tansultant-reactivation:
    description: "Реактивация клиентов Tansultant"
    owner: "roman"
    aliases: [cheap-fast, balanced]
    budget:
      amount_usd: 5
      period: daily        # daily | weekly | monthly
    limits:
      rpm: 60
      tpm: 100000

  my-telegram-bot:
    description: "Телеграм-бот"
    owner: "roman"
    aliases: [cheap-fast]
    budget:
      amount_usd: 1
      period: daily
    limits:
      rpm: 30
      tpm: 50000
```

#### `config/proxy.yaml`

```yaml
version: 1

request:
  timeout_seconds: 30
  num_retries: 2
  retry_after_seconds: 1

fallback:
  enabled: true
  trigger_on: [429, 500, 502, 503, 504, timeout]

logging:
  request_bodies: false      # НЕ менять без явного решения — на VPS осядет переписка
  response_bodies: false
  metadata: true

cache:
  enabled: false             # включается осознанно, semantic caching — вне scope
```

### 5.2 Команды

```
gwctl <command> [subcommand] [flags]
```

| Команда | Назначение |
|---|---|
| `gwctl apply` | Привести прокси к состоянию конфига. `--dry-run` — показать план без изменений |
| `gwctl diff` | Показать расхождение между конфигом и состоянием прокси |
| `gwctl validate` | Проверить конфиг локально (схема, ссылки на алиасы, дубликаты) — без сети |
| `gwctl key issue <consumer>` | Выпустить ключ. Печатает секрет **один раз** |
| `gwctl key list` | Список ключей: потребитель, алиасы, бюджет, статус, дата выпуска |
| `gwctl key revoke <consumer>` | Отозвать. `--grace 24h` — старый ключ живёт ещё сутки как deprecated |
| `gwctl key rotate <consumer>` | Выпустить новый + отозвать старый с grace. Композиция issue+revoke |
| `gwctl spend` | Отчёт по расходам. `--by consumer\|alias\|model`, `--since 7d` |
| `gwctl models` | Список алиасов с их текущим маппингом на вендорские модели |
| `gwctl health` | Проверить доступность прокси, БД, Redis и всех настроенных провайдеров |
| `gwctl version` | Версия бинарника |

**`rotate` — обоснование.** Пользователь выбрал ручной цикл revoke+issue.
`rotate` — не отдельная машинерия, а композиция двух существующих операций
поверх штатного `grace_period` LiteLLM. Стоит близко к нулю, спасает от
«отозвал ключ и уронил прод в воскресенье».

### 5.3 Реализация

| Аспект | Решение |
|---|---|
| Язык | Go 1.23+ |
| Module path | `github.com/romandots/llm-gateway` (уточнить при `git init` remote) |
| CLI framework | `spf13/cobra` |
| Конфиг | `gopkg.in/yaml.v3`, строгий парсинг (`KnownFields(true)`) |
| HTTP | stdlib `net/http` |
| Вывод | человекочитаемые таблицы по умолчанию, `--output json` для скриптов |
| Тесты | `go test`, юнит-тесты на трансляцию конфига и на reconcile-план |

**Reconcile должен быть идемпотентным.** `gwctl apply` дважды подряд —
второй раз не делает ничего и выводит «no changes». Это проверяется тестом.

**`gwctl apply` не трогает секреты.** Он создаёт/обновляет ключи и их атрибуты
(алиасы, бюджеты, лимиты), но никогда не печатает и не хранит значения ключей.
Секрет печатается только `key issue` / `key rotate`, единожды.

## 6. Makefile

Точка входа для всех рутинных операций. `make` без аргументов печатает справку
по целям (self-documenting через `##`-комментарии).

| Цель | Действие |
|---|---|
| **Сборка** | |
| `make build` | Собрать `gwctl` в `bin/gwctl` |
| `make install` | Установить `gwctl` в `$(GOBIN)` |
| `make fmt` | `gofmt` + `goimports` |
| `make lint` | `golangci-lint run` |
| `make test` | `go test ./... -race -cover` |
| **Стек** | |
| `make up` | Поднять docker compose (litellm, postgres, redis, caddy) |
| `make down` | Остановить стек |
| `make restart` | `down` + `up` |
| `make logs` | `docker compose logs -f` (`SERVICE=litellm` для одного сервиса) |
| `make ps` | Статус контейнеров |
| **Управление** | |
| `make validate` | `gwctl validate` — проверить конфиг локально |
| `make diff` | `gwctl diff` — расхождение конфига и прокси |
| `make apply` | `gwctl apply` |
| `make apply-dry` | `gwctl apply --dry-run` |
| `make key-issue CONSUMER=x` | Выпустить ключ |
| `make key-list` | Список ключей |
| `make key-revoke CONSUMER=x [GRACE=24h]` | Отозвать ключ |
| `make key-rotate CONSUMER=x [GRACE=24h]` | Ротировать ключ |
| `make spend [BY=consumer] [SINCE=7d]` | Отчёт по расходам |
| `make health` | Проверка здоровья стека и провайдеров |
| **Обслуживание** | |
| `make backup` | Дамп Postgres в `backups/YYYY-MM-DD-HHMM.sql.gz` |
| `make restore FILE=path` | Восстановить из дампа (с подтверждением) |
| `make smoke` | Smoke-тест контракта против поднятого стека (см. §12) |

Требования к целям, изменяющим состояние (`apply`, `key-revoke`, `restore`):
подтверждение или явный `--yes`, чтобы `make` в чужих руках не сломал прод
случайно.

`docs/GWCTL.md` — отдельный явный артефакт по требованию заказчика, а не раздел
README. Структура: обзор → конфигурация → команды (по одной секции на команду) →
сценарии → troubleshooting.

## 8. Развёртывание

```
deploy/

  Caddyfile
```

Сервисы: `litellm`, `postgres`, `redis`, `caddy`. Postgres и Redis не публикуют

**Секреты:** вендорские ключи (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`), пароль

`.env.example` — с плейсхолдерами. Оригиналы — в менеджере паролей владельца.

потребителям.

## 9. Наблюдаемость

Логируются **только метаданные**: ключ (идентификатор потребителя, не секрет),
алиас, реальная модель, входные и выходные токены, стоимость, latency, HTTP-статус,
факт fallback, `x-gw-request-id`. Тела запросов и ответов не пишутся — на VPS не
должна оседать переписка всех проектов.

Флаг `logging.request_bodies` в конфиге существует, по умолчанию `false`, и
помечен комментарием о последствиях. Включение — осознанное решение владельца.

Отчёты через `gwctl spend`:

```
$ gwctl spend --by consumer --since 7d
CONSUMER                   REQUESTS   TOKENS IN   TOKENS OUT   COST USD   FALLBACKS
tansultant-reactivation       12403     8.2M         1.1M        18.42          3
my-telegram-bot                 891     0.4M         0.2M         2.11          0
```

Внешний аптайм-мониторинг цепляется на `/health/liveness`.

## 10. Безопасность

| Требование | Реализация |
|---|---|
| Вендорские ключи не покидают VPS | Хранятся в `.env`, доступны только контейнеру LiteLLM |
| Потребитель не может обратиться к вендору напрямую | Единственный публичный интерфейс — контракт §3 |
| Принцип наименьших привилегий | Whitelist алиасов per-key, обязателен для каждого ключа |
| Ключи в git | Запрещено. `.gitignore` + проверка в `make validate` |
| Секрет ключа | Печатается один раз при `issue`/`rotate`, в БД хранится хэш (механизм LiteLLM) |
| TLS | Обязателен, Caddy с автоматическим сертификатом |
| Master key | Только для `gwctl`, никогда не выдаётся потребителям |
| Отзыв | `gwctl key revoke` — немедленный (`--grace 0`) или с окном |

## 12. Критерии приёмки

Функциональные:

1. `make up` поднимает стек, `make health` возвращает «всё зелено».
2. `gwctl validate` ловит: неизвестный алиас в `consumers.yaml`, дубликат
   потребителя, отсутствующий `targets`, невалидный период бюджета.
3. `gwctl apply --dry-run` печатает план; `gwctl apply` его применяет;
   повторный `gwctl apply` печатает «no changes».
4. `gwctl key issue` выдаёт рабочий ключ; запрос с ним к `/v1/chat/completions`
   с алиасом `balanced` возвращает `200` и непустой `usage`.
5. Запрос с вендорским именем модели (`claude-opus-5`) возвращает `400` с
   `error.code = unknown_model_alias` и списком доступных алиасов.
6. Запрос с алиасом, не входящим в whitelist ключа, возвращает `403`.
7. Запрос с отозванным ключом возвращает `401`.
8. При исчерпании дневного бюджета возвращается `429` с заполненными
   `retry_after` и `budget.*`.
9. Streaming-запрос отдаёт SSE и содержит `usage` в финальном чанке.
10. Tools: запрос с `tools` возвращает корректный `tool_calls`.
11. При искусственно сломанной первичной модели алиаса запрос отрабатывает через
    fallback и отдаёт `x-gw-fallback: true`.
12. `GET /v1/models` возвращает только алиасы, разрешённые предъявленному ключу.
13. `gwctl spend --by consumer` показывает ненулевой расход после тестовых запросов.
14. В логах отсутствуют тела запросов и ответов.
15. `gwctl key rotate --grace 24h` оставляет старый ключ рабочим, новый — тоже.

Качественные:

16. `make test` — зелёный, покрытие `internal/` не ниже 70%.
17. `make lint` — без замечаний.
18. `docs/GWCTL.md` описывает каждую команду и каждый флаг; примеры вывода
    соответствуют фактическому.
19. `docs/CONTRACT.md` достаточен, чтобы разработчик-потребитель подключился без
    вопросов к владельцу.

## 15. Версионирование

SemVer. Версия в `CHANGELOG.md` и git-теге `vX.Y.Z`.

- **MAJOR** — обратно несовместимое изменение публичного контракта §3
  (переименование или удаление алиаса, изменение формата ошибки, смена схемы auth)
- **MINOR** — новый алиас, новая команда `gwctl`, новый провайдер
- **PATCH** — багфикс, ремап алиаса на другую вендорскую модель (контракт не меняется)

Ремап алиаса на другую модель — **PATCH**, и это ровно тот случай, ради которого
строился шлюз: потребители не замечают.
